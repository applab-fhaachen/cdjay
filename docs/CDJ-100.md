## Working Principle
! This is pure speculation, we still need to figure out a few things:

### Switches
The switches are read through multplexing using the lines S1-5 as Outputs and KD0-2 as Inputs.
To figure out which switch is pressed, pull S1 high, read KD0-3, set S1 log, set S2 high, read KD0-3, set S2 Low,...

So far so good. But at the same time S1-15 are also used to drive the display, so all that needs to work with quite some refresh rate. That should be measureable by probing G1 with an oscilloscope. Yes it is, ~100Hz

### Display

The display in the CDJ-100 is a Vacuum Fluorescent Display (VFD) and these are a bit different than an LCD, which is why we need a special controller. 

The display is split in 11 grids with 12 segments.
The G1-G11 lines are used to activate the respective Grid, whose value can then be set using the S1-12 lines. Since we don't have 15, but only 12 S-Lines there needs to be a trick somewhere. 
Pin 6 and Pin 15 (S3 & S12) share the same signal S3 to form a vertical line on the 14-segment characters (G3 to G8).
Pin 10 and 11 (S7 & S8)  share the same signal S6 form a horizontal line on the 14-segment characters (G3 to G8).

Driving a VFD requires some unusual voltages. While enabling a segment is done by applying +5V, it is immediately disabled again by applying a negative bias voltage to increase contrast. The original display driver uses -30V as bias voltage. 

The PT6302 Dislpay Driver IC [Info](https://support.newhavendisplay.com/hc/en-us/articles/4414910103063-PT6302) [Datasheet](https://support.newhavendisplay.com/hc/en-us/article_attachments/4414910097047) seems to be the right choice as it offers 16 Grids and 64 Segments. The PT6312 is cheaper but can only drive 11 groups with 11 segments max, while we need 11 groups with 12 segments. 

There are some libraries out there to use these chips.
https://github.com/the-real-mcarn/PT6302
https://github.com/ysard/PT6312_VFD_Arduino_Library

The LC75710 is also a good candidate. 

The -30V Bias Voltage, luckily, comes from the trans board assy as VLOAD.

#### Synchronizing with the chip for multiplexing the button readout

We need a way to synchronize with the chip in order to read out the KD-Lines. We cannot do that in parallel since the Values on the S1 to S5 depend on what's going to be shown on screen. 

However, we have some unused G-Lines from the PT6302 which we can use as trigger on the RPi. If we connect these to inputs, and set the S-Lines accordingly, we can get an interrupt, read KD0-2 and be happy. We have 16 Group outputs on the PT6302, of which only 11 are used for the display. The remaining 5, G12-G16, are connected to the RPi (don't forget the Diodes). We set the content of these groups to fixed outputs, i.e., for G12 only S1 is enabled, for G13 only S2 is enabled, ..., for G16 only G5 is enabled. This contradicts the idea of multiplexing to save pins a bit, but since we don't have a direct synchronization between the display controller and the RPi, this seems like a feasible solution. 

### LEDs
The LEDs are controlled through line S4, S8, S9 and group 1. The trick here, is that in group 1, these lines are not used, therefore ignored and can thus be used to drive the LEDs. The according segments need to be enabled disabled in the display driver. 


### Pitch Fader
The pitch fader is a classical adjustable voltage divider. At minimum, the output voltage ADIN is 0V, whereas at maximum, it is +5V. The neutral position (0%) is important in order to play tracks at their original speed. In order to compensate possible fader drift through ageing, the circuit has the CT-output. This returns a constant voltage. Connect this to an ADC to have the exact reference for ADIN at the neutral position. 

The VREF for the ADC is +5V. The GNDREF for the ADC is GNDD.
